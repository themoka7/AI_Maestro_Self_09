# WebSquare 새 화면 만들기

먼저 `.claude/skills/websquare-common-query/SKILL.md` 와 `config/ws-config.json` 을 읽는다.

사용자가 생성기(index.html)에서 만든 **에이전트 요청문이나 명세 JSON을 이미 붙여넣었다면** 아래 질문은 건너뛰고 6단계로 간다.

## 1. 화면 유형 (AskUserQuestion)

| 값 | 이름 | 설명 |
|---|---|---|
| `search` | 조회형 | 검색조건 + 조회 전용 그리드 |
| `edit` | 그리드 편집형 | 조회 + 신규/삭제/저장 |
| `md-tb` / `md-lr` | 마스터-디테일 상하/좌우 | 마스터 선택 시 상세 그리드 조회 |
| `grid-form` | 목록 + 상세 폼 | 목록 선택 시 아래 폼에서 편집 |
| `meta` | 공통 데이터 조회 등록 | 메타 조회용 SP + 관리 화면 등록값 |

선택지가 4개를 넘으므로 "조회 계열(조회형/공통 데이터 조회)" 과 "편집 계열(편집형/마스터-디테일/목록+폼)" 로 한 번 나눠 묻거나, 사용자의 말에서 이미 드러나면 묻지 않는다.

## 2. 디자인 (AskUserQuestion, 한 번에 묶어서)

- 검색영역 한 줄 칸 수: 4칸(기본) / 2칸
- 엑셀 다운로드: 사용 / 미사용
- 안내문구: 있음(문구 받기) / 없음
- 마스터-디테일이면 상하 / 좌우

## 3. 기본 정보 (자유 입력으로 받기)

화면 ID, 화면명, DB(`config.dbs`), 대상 테이블, 조회 SP 이름, (편집 계열) 저장 SP 이름, (마스터-디테일) 연결 키·상세 테이블·상세 SP.
SP 이름은 사내 규칙(`시스템접두어_업무_현황_조회` / `_저장`)을 따르도록 제안해 준다.

## 4. 조회조건

순서 = SP 파라미터 선언 순서. 유형은 `TEXT, NUMBER, SELECT, DATE, YM, SYEAR, TERM, YEAR, SESSION`.
- 학년도 바로 다음이 학기면 한 칸("학년도/학기")으로 합쳐진다.
- SELECT·TERM 은 공통코드 그룹이 필요하다. `config.codes` 에 있는 것은 선택지로 보여 주고, 없는 그룹이면 이름·조건을 받아 `config/ws-config.json` 의 `codes` 에 추가한다(조건 SQL 조각이 있으면 `getCodeByEtcParam`).
- 세션 파라미터(`SESSION_USER_ID`, `SESSION_USER_DEPT_CD` 등)는 화면에 안 나오고 프레임워크가 채운다.

## 5. 컬럼

컬럼 ID·헤더명·폭·정렬·키 여부. 편집 계열이면 편집 유형(text/number/select/date/check), 필수, maxbyte, 콤보면 공통코드 그룹.
사용자가 테이블 정의나 SELECT 문을 주면 거기서 뽑아 표로 보여 주고 확인만 받는다.

## 6. 생성과 다듬기

1. 명세를 `specs/<화면ID>.json` 으로 저장 (형식은 `specs/examples/*.json` 참고).
2. `node tools/gen.js specs/<화면ID>.json` → `out/<화면ID>/`
3. 출력된 "확인 필요" 경고를 하나씩 처리한다. 사용자 확인이 필요한 것(사내 템플릿 값, 감사 컬럼명 등)은 모아서 한 번에 묻는다.
4. SP의 `[dbo].[테이블명]`, WHERE, 조인을 실제 업무에 맞게 고친다.
5. `node tools/check.js out/<화면ID>` 통과까지 고친다.
6. 결과는 파일 목록 + 남은 확인 사항만 짧게 보고한다. 전체 코드는 요청할 때만 보여 준다.

작업량이 크면 `websquare-dev` 에이전트에 명세 파일 경로를 넘겨 4~5단계를 맡긴다.
